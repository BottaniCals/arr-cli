# Implementation Plan

## Task Overview

This plan delivers the `arr-cli-mvp` Python package: five thin, read-only CLIs (`jellyfin`, `radarr`, `sonarr`, `maintainerr`, `seerr`) backed by a shared `arr_cli.facade` package that owns configuration, HTTP transport, authentication, error mapping, and output formatting. The work is ordered foundation-first so each layer can be unit-tested in isolation: packaging skeleton → config → transport → output → CLI parser → per-service command modules → performance budgets → CI scripts → documentation. All 29 commands (8 jellyfin + 6 radarr + 6 sonarr + 3 maintainerr + 6 seerr) are enumerated as atomic subtasks referencing exact HTTP paths from `design.md` and acceptance criteria from `requirements.md`. Total: **20 main tasks, 55 atomic subtasks**, implementable in ~20 focused agent sessions.

Conventions used throughout:
- All file paths are relative to `/projects/media-cli/`.
- Python 3.11+ stdlib (`tomllib`, `argparse.BooleanOptionalAction`, `urllib.parse.quote`) is assumed; `requests >= 2.28` and `PyYAML >= 6.0` are the only third-party runtime deps.
- Tests live under `tests/unit/` and use `unittest` + `unittest.mock` + `responses`; `pytest` is the runner only.
- `pyproject.toml` declares console scripts `jellyfin`, `radarr`, `sonarr`, `maintainerr`, `seerr` mapping to `arr_cli.<service>:main`.

- [x] 5. Implement optional retry layer with exponential backoff and jitter
  - [x] 5.1 Create `arr_cli/facade/retry.py` with `with_retry(fn, *, attempts, deadline)` closure runner
    - Default `attempts = 0` means single attempt (no retries); `attempts = 2` means up to 2 attempts total
    - Use `time.sleep` with exponential backoff: `base = 0.5s`, `delay = base * (2 ** (attempt-1))`, then `+ random.uniform(0, 0.25)` jitter
    - Respect `deadline` as absolute wall-clock cap; stop retrying when `time.monotonic() - start > deadline`
    - Only retry on `NetworkError` (network-class); never retry on `AuthError`, `HttpError`, or `ParseError`
    - Final failure re-raises the last `NetworkError` with attempt count in the message
    - _Requirements: REQ NFR-Reliability (retry policy)_
  - [x] 5.2 Wire `with_retry` into `transport.get` based on `cfg.retry`
    - If `cfg.retry > 0`, wrap the requests call in `with_retry(..., attempts=cfg.retry + 1, deadline=cfg.deadline)`
    - If `cfg.retry == 0`, skip retry layer entirely (preserves the 2-second cold-start budget)
    - _Requirements: REQ NFR-Reliability_
